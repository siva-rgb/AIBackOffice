## Quiz-me Q+A (L4 protocol)

**Q1 · Design decision:** Why did M2.2 split `test.yml` (every-PR) from `cron.yml` (schedule-only) instead of one workflow with both triggers?
**A:** A failing schedule job must NOT block PR merges — they're independent failure surfaces. Combining them would mean a 02:00 UTC Stripe outage prevents merging a doc fix at 14:00. Two workflows, two failure domains.

**Q2 · Edge case:** What happens when a contributor forgets to run `npm ci` and uses a stale `node_modules` — does the gate still catch that?
**A:** Yes. The GitHub Actions runner does a clean `npm ci` (lockfile-deterministic) before `npm run lint` / `tsc` / `jest`. The contributor's stale `node_modules` is irrelevant — CI has its own sandbox. The lockfile-pinned `eslint@8.57.1` + `eslint-config-next@14.2.35` is what matters, and `npm ci` reproduces that exactly.

**Q3 · Change impact:** The `_all_api_routes()` helper in `test_plan_gating.py` — does any other test depend on the old `app.routes` flat iteration?
**A:** No. `app.routes` is only consumed in `test_plan_gating.py`; `_gated_routes()` and `test_every_policy_route_actually_exists()` were the only call sites, both updated to use `_all_api_routes()`. No collateral.
