1. Background

M7 was the security-hardening milestone in Kora's Phase 1 (30-90 day) hardening track. Five independently-assignable sub-items, each targeting a known gap. The key insight: these are not large refactors — they are surgical additions to existing code paths, with tests that prove the old behavior was insecure and the new behavior closes the gap.

Each sub-item addresses a different trust boundary:

M7a — Authorization

Stripe downgrade must actually block premium endpoints.

M7b — OAuth State

Redirect callback state must be tamper-proof, not a raw user ID.

M7c — Pub/Sub JWT

Gmail push endpoint must authenticate the sender (Google), not just accept any POST.

M7d — CSP Headers

Content-Security-Policy must not allow 'unsafe-inline' or 'unsafe-eval' in production.

M7e — PII Encryption

Tax IDs and bank details need application-layer encryption, not just DB-at-rest.

AFTER

def _get(row):
  if row.tax_id.startswith("enc_v1:"):
    return decrypt(row.tax_id[7:])
  return row.tax_id  # legacy plaintext

3. Code Walkthrough

M7b — oauth_state.py

The OAuth state token is a HMAC-SHA256 of {user_id, expiry, nonce}. The server verifies by recomputing the HMAC. The secret is the existing TOKEN_ENCRYPTION_KEY (already fail-closed per M3). No server-side session store needed — the state is self-encoding, self-authenticating. 

# oauth_state.py
import hmac, hashlib, json, time, os

def sign(user_id: str, ttl: int = 300) -> str:
    payload = {"kid": user_id, "exp": time.time() + ttl, "jti": os.urandom(8).hex()}
    return hmac.new(KEY, json.dumps(payload).encode(), hashlib.sha256).hexdigest()[:24] + ":" + b64(payload)

def verify(token: str) -> str | None:
    mac, rest = token.split(":", 1)
    expected = hmac.new(KEY, rest.encode(), hashlib.sha256).hexdigest()[:24]
    if not hmac.compare_digest(mac, expected):
        return None
    payload = json.loads(b64decode(rest))
    if time.time() > payload["exp"]:
        return None
    return payload["kid"]   # the user_id

M7c — pubsub_auth.py

Google's Pub/Sub push endpoints carry an OIDC JWT in the Authorization: Bearer header. pubsub_auth.py verifies the JWT against Google's OIDC discovery endpoint and checks that the audience matches GMAIL_PUB_AUDIENCE (the push). 

def verify_push_token(token: str) -> bool:
    if not settings.GMAIL_PUB_AUDIENCE:
        return True  # dev/local no-op
    from oauthlib.oidc import verify_token
    claims = verify_token(token, issuer="accounts.google.com", audience=settings.GMAIL_PUB_AUDIENCE)
    return claims is not None

M7e — PII encryption at store boundary

A prefix-based encoding at the store boundary, modeled on the pattern used by Supabase's PGP extension: new writes prefix v1: "read" strips the prefix and decrypts. Legacy plaintext has no prefix, so it passes through as-is.

def _encrypt_pii(value: str) -> str:
    if not value or value.startswith("enc:v1:"):
        return value
    return "enc:v1: " + encrypt(value)

def _decrypt_pii(value: str) -> str:
    if value and value.startswith("enc:v1:"):
        return decrypt(value[7:])
    return value  # legacy plaintext

4. Key Design Decisions

HMAC over server-side session

HMAC tokens are self-contained (no server store). Multi-worker safe. OAuth callbacks must survive process restarts and multi-instance deploys. HMAC avoids a shared session store.

Pub/Sub JWT optional

If GNOTPUB_AUDIENCE is unset -> skip JWT verify. Useful for local zero-config dev. In production, must be set or gmail events are not authenticated.

Nonce CSP, not hash CSP

Nonce-based CSP lets the server control which scripts are trusted per-request (inject a fresh nonce in the response header). Hash CSP requires the inline script content to be known at server-start-up — impossible for dynamic docs.

Prefix-based PII encryption

Pure backward-compatible: legacy plaintext passes through unchanged. New writes are encrypted, Pre-migration rows are readable forever. No migration needed to back-fill.
