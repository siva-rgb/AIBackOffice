## Bookkeeper

### CSV format expected
```
Date,Description,Amount,Type
2024-01-15,Adobe Creative Cloud,-52.99,expense
2024-01-18,Client payment - Project Alpha,3500.00,income
```

Accept variations: `date/DATE`, `description/DESCRIPTION/memo/MEMO`, `amount/AMOUNT/debit/credit`. Auto-detect column names on upload. If format unrecognised, show helpful error with example CSV.

### Categorization taxonomy
Income categories: `client_payment`, `retainer`, `royalty`, `refund_received`, `other_income`
Expense categories:
- `software_subscriptions` (Adobe, Figma, Notion, etc.)
- `hardware_equipment`
- `marketing_advertising`
- `professional_services` (accountant, lawyer)
- `travel_transport`
- `meals_entertainment`
- `office_supplies`
- `utilities_internet`
- `insurance`
- `education_training`
- `contractor_payments`
- `bank_fees`
- `other_expense`

### P&L PDF structure
Page 1: Summary (total income, total expenses, net profit, profit margin %)
Page 2: Income breakdown by category (table + bar chart description)
Page 3: Expense breakdown by category (table)
Page 4: Top 10 transactions by amount
Footer: "Generated by Kora AI — kora.app"

### Edge cases to handle
- Duplicate transactions: check (user_id + date + description + amount) before insert
- Multi-currency: store original currency, convert to USD at upload time using hardcoded rate (MVP) or exchange rate API
- Negative income rows: treat as expense adjustment not separate expense
- Very large files (>1000 rows): process in background, show progress bar, notify when done

## Invoices

### Invoice object structure
```typescript
interface Invoice {
  id: string;
  userId: string;
  invoiceNumber: string;      // Auto-generated: INV-2024-001
  clientName: string;
  clientEmail: string;
  lineItems: LineItem[];
  subtotal: number;
  taxRate: number;            // Percentage, 0 if not applicable
  taxAmount: number;
  total: number;
  currency: string;           // Default USD
  status: InvoiceStatus;
  dueDate: Date;
  notes?: string;
  contractId?: string;        // FK to contracts table
  sentAt?: Date;
  paidAt?: Date;
  followUpCount: number;
  lastFollowUpAt?: Date;
}

interface LineItem {
  description: string;
  quantity: number;
  rate: number;
  amount: number;
}
```

### Invoice email template
Subject: `Invoice [INV-NUMBER] from [Business Name] — $[AMOUNT] due [DATE]`

Body: Plain HTML email. Clean, minimal. Shows:
- Your business name + logo placeholder
- Invoice number, date issued, due date
- Line items table
- Total (with tax breakdown if applicable)
- Payment link (Stripe Payment Link or bank details)
- "View invoice online" button

### Follow-up schedule logic
```
Day 0: Invoice sent
Day +3 after due date: Follow-up 1 (gentle reminder)
Day +7 after due date: Follow-up 2 (firm)
Day +14 after due date: Follow-up 3 (final notice — includes payment demand if contract linked)
Day +21+: No more auto follow-ups. Alert user to take manual action.
```

AI generates each email dynamically — NOT canned templates. Tone escalates across follow-ups.

### Invoice PDF structure
Page 1:
- Header: your business name + logo
- "INVOICE" heading + invoice number
- Billed to: client details
- Invoice date + due date
- Line items table
- Subtotal / tax / total
- Payment instructions
- Thank you note

## Contracts

### Contract wizard UX flow
```
Step 1: Select type
  → NDA | Freelance Agreement | Service Contract | Refund Policy | IP Transfer

Step 2: Parties
  → Your legal name / business name
  → Client legal name / business name
  → Both addresses (optional but recommended)

Step 3: Key terms (type-specific questions)
  NDA:
    → Direction: mutual or one-way
    → Duration: 1/2/3/5 years
    → What's confidential: describe in plain English

  Freelance Agreement:
    → Project description
    → Deliverables (list)
    → Timeline: start date, deadline
    → Payment: fixed fee or hourly
    → Total amount / hourly rate
    → Payment schedule: upfront / milestone / on completion
    → Revision rounds: how many included
    → IP ownership: client or freelancer retains

  Service Contract:
    → Service description
    → Duration: one-time or ongoing
    → Monthly retainer amount
    → Payment due date each month
    → Termination notice period

  Refund Policy:
    → Refund window: 14/30/60/no refunds
    → Conditions for refund
    → Process for requesting refund

  IP Transfer:
    → Description of work being transferred
    → Compensation amount
    → Whether any rights reserved

Step 4: Jurisdiction
  → Country dropdown
  → State/Province (if USA, Canada, Australia)

Step 5: Review & Edit
  → Rendered preview (Markdown → HTML)
  → Each clause has a plain-English explanation tooltip
  → "Regenerate clause" button per section
  → Edit mode (user can tweak text)

Step 6: Export
  → Download PDF
  → Send to client (email with signing link — MVP: simple email, no e-sign integration)
  → Copy link
```

### Contract PDF structure
Page 1: Title, parties, date
Pages 2–N: Contract body, organized by numbered sections
Last page: Signature blocks (Name, Signature, Date, Title — for both parties)
Footer: Page numbers, "Prepared with Kora AI — kora.app | Not a substitute for legal advice"

### Disclaimer (required on every contract)
Include this text at the top of every generated contract:
> "This document was generated by Kora AI as a starting point. It has not been reviewed by a licensed attorney. For complex transactions or disputes, please consult qualified legal counsel in your jurisdiction."

## Cashflow

### Forecast algorithm
```
1. Baseline: average daily income/expense over last 90 days
2. Known upcoming income: open invoices × probability weight
   - sent, < 7 days overdue: 85% probability
   - sent, 7–14 days overdue: 60% probability
   - sent, 14+ days overdue: 30% probability
   - draft: 0%
3. Known upcoming expenses: recurring expenses detected from history
   (recurring = same description ±10% amount, same ±3 days each month, 2+ occurrences)
4. Apply seasonal factor (Gemini suggests based on business category)
5. Three scenarios:
   - Optimistic: income at 110% base, expenses at 90% base
   - Expected: base values
   - Conservative: income at 75% base, expenses at 115% base
```

### Chart data format
```typescript
interface ForecastPoint {
  date: string;           // ISO date
  actual?: number;        // Only for past dates
  optimistic?: number;    // Only for future dates
  expected?: number;      // Only for future dates
  conservative?: number;  // Only for future dates
  events?: string[];      // Invoice due dates, recurring expenses
}
```

### Danger zone threshold
Show red warning banner when:
- Conservative scenario balance < 0 within 14 days
- Expected scenario balance < 0 within 30 days

## Alerts

### Alert generation prompt structure
See `agents.md` for full prompt. Context sent to Gemini:
- Last 30 days transactions (aggregated by category)
- Current open invoice amounts + ages
- Last forecast balance
- Any recent anomalies

### Alert deduplication
Before inserting a new alert, check: has this `type` fired for this `user_id` in the last 7 days?
If yes: skip (don't spam users with same alert daily).
Exception: `cashflow_critical` can fire daily.

### Alert notification channels (MVP)
1. In-app notification bell (primary)
2. Daily digest email (grouped, not one email per alert)

Push notifications: future scope.

### Alert types reference
| type | severity | trigger | message template |
|---|---|---|---|
| `cashflow_warning` | warning | balance < 0 in 30 days | "Your cash flow may go negative in ~{X} days." |
| `cashflow_critical` | critical | balance < 0 in 14 days | "Urgent: cash flow projected negative in {X} days." |
| `invoice_pile_up` | warning | 3+ invoices overdue | "{N} invoices totalling ${X} are overdue." |
| `tax_quarter` | info | 14 days before quarter end | "Q{N} ends in 14 days. {X} expenses may be deductible." |
| `expense_anomaly` | warning | expense > 2× monthly avg | "Unusual expense: ${X} in {category} (avg ${Y}/mo)." |
| `deduction_opportunity` | info | recurring non-deductible expense | "{Description} may be tax deductible. Flag it?" |

## Cross-Module

### Database triggers to implement
Use Supabase database webhooks or Postgres triggers to fire cross-module logic.

**Trigger: contract_status_to_signed**
```sql
-- Webhook fires when contracts.status changes to 'signed'
-- Cloud Run endpoint: /api/cross-module/contract-signed
```

Handler logic:
1. Fetch contract terms JSON
2. Extract payment schedule (if any)
3. For each payment milestone:
   - Create draft invoice with correct amount and due date
   - Link invoice to contract via `contract_id`
4. Create alert: "Contract signed with {client}. {N} invoices created."
5. Log to `agent_logs` with `triggered_by: cross_module`

**Trigger: invoice_follow_up_count_reaches_2**
```sql
-- Webhook fires when invoices.follow_up_count = 2 AND contract_id IS NOT NULL
-- Cloud Run endpoint: /api/cross-module/payment-demand
```

Handler logic:
1. Fetch linked contract
2. Extract payment terms clause text
3. Call Gemini: generate formal payment demand letter referencing contract
4. Attach letter to Day 14 follow-up email as PDF
5. Log to `agent_logs`

### Cross-module action log format
```json
{
  "agent_type": "cross_module",
  "action": "Generated payment demand letter from contract terms",
  "triggered_by": "cross_module",
  "input": {
    "invoice_id": "...",
    "contract_id": "...",
    "overdue_days": 14,
    "amount_owed": 3500,
    "payment_clause_excerpt": "Payment due within 30 days of invoice..."
  },
  "output": {
    "email_sent": true,
    "pdf_generated": true,
    "letter_preview": "Dear [Client], This letter serves as formal notice..."
  }
}
```
