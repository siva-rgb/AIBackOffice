## Plan

1. **Config** — add `EMBEDDING_DIM: int = 1536` and `AGENT_MEMORY_VECTOR_BACKEND: str = "jsonb"` to `app/config.py`. Default keeps the live app on the proven JSONB path; the flag only flips when an operator has run the migration + backfill.
2. **Migration** — `backend/migrations/2026-07-29_pgvector_agent_memory.sql`:
   - `CREATE EXTENSION IF NOT EXISTS vector;`
   - `ALTER TABLE agent_memory ADD COLUMN IF NOT EXISTS embedding_vec vector(1536);`
   - HNSW index: `CREATE INDEX IF NOT EXISTS idx_agent_memory_embedding_vec_hnsw ON agent_memory USING hnsw (embedding_vec vector_cosine_ops);` (per-user rows are small; HNSW is faster to set up than IVFFLAT and is the modern default per pgvector docs)
   - `match_agent_memory(user_id uuid, query_embedding vector(1536), match_threshold float, match_count int, filter_client uuid, filter_kinds text[])` SECURITY DEFINER RPC that filters by `auth.uid() = user_id` and applies optional `client_id` + `kinds` filters; returns `(id, kind, client_id, ref_type, ref_id, content, salience, source, metadata, created_at, updated_at, similarity)`.
   - RLS unchanged — `auth.uid() = user_id` policy still applies; the RPC is `SECURITY DEFINER` so it can run with the caller's auth context but doesn't bypass RLS for reads.
3. **Backfill** — `backend/scripts/backfill_agent_memory_vectors.py`: idempotent, page-based; reads rows where `embedding IS NOT NULL AND embedding_vec IS NULL`, converts JSONB list to pgvector literal, writes back via `UPDATE ... SET embedding_vec = ARRAY[...]::vector`. Per-batch progress logging; dry-run flag.
4. **Backend helpers** (`supabase_store.py`):
   - `vector_search_agent_memory(user_id, query_embedding, k, *, client_id, kinds, min_similarity)` — calls `match_agent_memory` via the M1 wrapper (PostgREST RPC is a non-table read; documented as wrapper-respecting — `repo()` already covers RPC calls in M1; verify before merge)
   - Existing `upsert_agent_memory` extended to write `embedding_vec` alongside `embedding` JSONB when the embedding is non-None (single source of truth — the `embedding` JSONB column stays for backward compat / mock backend; new column is the ANN-indexed one)
5. **Service-layer dispatch** (`memory_recall.py`):
   - In `recall()`, after the existing load-all-and-score branch, add a **pgvector branch** that runs when:
     - settings backend is `pgvector`
     - `embeddings.is_enabled()` (have a query vector)
     - query vector is not None
   - This branch: calls `store.vector_search_agent_memory(user_id, q_vec, k * 3, ...)`, applies the **same scoring formula** (semantic + lexical + salience + recency) to the candidate set returned by the index, and returns the top-k. Net effect: from `O(N)` Python cosine → `O(log N)` ANN search with identical ranking semantics.
   - The JSONB path is preserved verbatim so `memory_recall.remember/recall/build_recall_brief/reindex/stats` signatures don't change.
6. **Benchmark** — `backend/tests/perf/test_memory_recall_benchmark.py`:
   - Quality: 20-row seeded fixture with controlled semantic relationships; measures recall@5 with a deterministic `fake_embeddings` fixture; asserts pgvector-path >= JSONB-path on the same fixture.
   - Latency: seeds 1000 rows per user, times 100 queries, reports p50/p95; logs (does not assert — the test is informational; the gate is the reported number in the checkpoint).
   - Benchmark is **dual-run**: when run with the default `AGENT_MEMORY_VECTOR_BACKEND=jsonb` it exercises the JSONB path and prints numbers; with `=pgvector` it exercises the new path. The gate is "pgvector meets or beats JSONB" which the test asserts on a pre-registered gate fixture.
7. **Schema doc** — append the new column + index + RPC to `docs/specs/schema.sql`.

- decisions:
  1. **HNSW over IVFFLAT.** Per-user memory is 100s–1000s rows; HNSW has no training step, supports incremental inserts without rebuild, matches IVFFLAT on recall at this scale. vector_cosine_ops matches `_cosine()` in `memory_recall.py`.
  2. **JSONB + vector(N) dual-column.** Don't drop the JSONB `embedding` column — it's the canonical write target (mock-mode parity, no extension needed for tests, idempotent backfill source). New `embedding_vec` column is ANN-indexed. `upsert_agent_memory` writes both so new rows are immediately searchable by pgvector branch without waiting for backfill.
  3. **SECURITY DEFINER RPC with explicit auth.uid() check inside the body.** RLS alone is not enough because SECURITY DEFINER bypasses RLS for the function's own reads. An explicit `IF v_auth IS NULL OR v_auth <> p_user_id THEN RETURN;` is the tenant boundary. Documented in the migration comments.
  4. **3x k over-fetch from the index.** Index ranks by ANN similarity alone; final score mixes lexical + salience + recency. A wider candidate window lets the hybrid re-ranker correct the index's blind spots.
  5. **Same hybrid scoring formula on both paths.** `memory_recall.recall()` applies `0.60*sim + 0.20*lex + 0.12*sal + 0.08*rec` (semantic) or `0.70*lex + 0.18*sal + 0.12*rec` (lexical-only) to candidates regardless of how they were selected — JSONB-path and pgvector-path produce identical ranking on the same fixture.
  6. **Default backend stays `jsonb`.** `AGENT_MEMORY_VECTOR_BACKEND=jsonb` is the proven pre-M10 path. Operators flip to `pgvector` only after applying the migration + running the backfill.
