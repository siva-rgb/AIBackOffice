## L4 · Q+A (human-confirmed)
1. Answer: HMAC-signed `state` prevents state forgery/account-binding attacks (attacker can’t substitute another user_id); it also avoids needing server-side session storage by making the server-side verification possible from the token itself (includes expiry).
2. Answer: If `GMAIL_PUBSUB_AUDIENCE` is unset, verification is skipped (dev/local convenience). If audience is set and the JWT is invalid/expired, verification fails and `/api/gmail/push` returns `401`.
3. Answer: Reads remain backward compatible because legacy plaintext values (no `enc:v1:` prefix) pass through unchanged; new writes encrypt at the store boundary and are prefixed. On read, the decrypt logic transparently decrypts `enc:v1:` values.
