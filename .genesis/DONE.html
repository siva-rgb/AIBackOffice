1 · The Locked Spec (what we are building)

Cognitive job: Perform the back-office reasoning of a freelancer / small business — categorize transactions, chase invoices, draft and risk-review contracts, forecast cash, and surface what needs attention — under supervised autonomy, with every AI action attributed to a real model, token count, latency, and cost.

Inputs: bank/transaction CSVs · invoice & contract state · Gmail / Drive / Calendar signals · Notion tasks · user chat and stated goals  →  Outputs: categorized ledger + P&L PDF · invoices, follow-up and demand letters · contract drafts + clause explanations + risk reviews · 90-day 3-scenario cash forecast · deduped alerts / digests · task-ledger updates (two-way with Notion)

Autonomy level: Supervised, split by blast radius. Read-only analysis (categorization, forecasting, briefing, risk review) runs autonomously. Anything outbound or money-moving is draft-then-approve — the agent composes, a human releases.  |  Human-in-the-loop points: invoice follow-up & payment-demand letters (supervisor.approve_task → deliver=True) · contract send · propose_task · every Gmail send. Preview and bulk/cron paths are deliberately draft-only so nothing mass-emails by surprise.

Failure tolerance: Low for outbound / financial actions — the system must degrade to draft-only (no send, clear note) rather than send something wrong; a retry must never double-send. Medium for analysis — a bad categorization or forecast is correctable in the review queue. Mock LLM + in-memory store must keep the app fully runnable offline.  |  Trust boundary: multi-tenant SaaS over other people's financial records. Supabase JWT verified at the edge; the service-role key bypasses RLS and is backend-only, never exposed to the frontend; per-user Google/Notion OAuth tokens stored encrypted; all LLM input passes sanitize_prompt_input(); cron routes gated by CRON_SECRET.

Filled during Genesis step G0 (Cognitive Design) via agentic-swe-master. Diagnostic: scope = extend existing system · AI = yes, heavily · distributed = yes · trust boundary = yes, multi-tenant + financial · active phases = 9, 11, 13, 19.
