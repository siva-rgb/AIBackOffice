M3 — Token Encryption Fail-Closed

Security Fix 10/10 Tests Pass Fail-Closed 2026-07-31
Before: _fernet = None escape hatch let the app boot without TOKEN_ENCRYPTION_KEY. Every restart with a missing key = new random Fernet key = silently destroy all encrypted OAuth / Notion / Stripe tokens. No error, no warning.
After: Module-level _fernet: Fernet = load_key() at import time. Missing or malformed key → StartupError(RuntimeError) → process exits code 1 with a descriptive diagnostic. The app refuses to start rather than silently corrupting tokens.

What M3 Built

M3.1 — Remove Fallback Key

Removed _fernet = None module-level escape hatch. The lone Fernet.generate_key() call now exists only in a test helper docstring and is never invoked at runtime. No path to generate a random key silently.

M3.2 — StartupError + load_key()

Custom class StartupError(RuntimeError) exception. load_key() validates the Fernet key format; _read_key() strips whitespace before checking emptiness. On failure, process exits code 1 with message:

TOKEN_ENCRYPTION_KEY is not set. Generate one with: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())" Refusing to start: every restart would silently destroy all encrypted OAuth/Notion/Stripe tokens.

Design Decisions

_fernet (singleton)
  • Stricter than required Mock-mode escape hatch removed entirely. Even for mock mode, missing key fails the process. Tests get a fixed Fernet key via conftest.py.
  • Whitespace-safe _read_key() strips whitespace before checking emptiness — handles accidental trailing newlines from env files.
  • ValueError load_key() raises ValueError for malformed keys (wrong length, non-base64 characters).
  • InvalidToken On decrypt failure, callers see: "Google/Notion/Stripe Connect reconnect needed".
