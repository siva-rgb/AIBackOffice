### Caveats from §5 evaluation

**Mock-mode escape removal — verdict: SAFETY IMPROVEMENT, not a spec violation.**

The literal context-graph invariant reads: `load_key() MUST raise
StartupError (not fall back to random key) if TOKEN_ENCRYPTION_KEY is
unset in production mode.` The implementation removes the mock-mode
escape regardless of `KORA_DATA_BACKEND`. This is stricter than the
literal invariant but matches the **inv_token_encryption_startup**
intent: "No silent data loss." A developer running the suite locally in
mock mode without setting the env var previously got a silent default
(no exception), which is exactly the failure class M3 is closing.
Catching that class for free is in-scope under the spirit of the gate
("starting the app without TOKEN_ENCRYPTION_KEY exits non-zero with a
descriptive error instead of booting") — note the gate does not say
"unless KORA_DATA_BACKEND=mock." Approving.

**Same-session verification — verdict: INSUFFICIENT per strict LOOPS.md, acceptable for now.**

LOOPS.md §244 explicitly says the L4 checker must be a **different model
with fresh context** ("keep maker away from checker"). This verification
ran in the same model, same session. Independent-command evidence mitigates
this (all gate commands were re-run, no claimed exit codes trusted), but it
is not a full LOOPS.md-compliant L4. Recommend a separate-model L4 pass
**before** flipping PLAN.md / DONE.html to `[x] / done`. If the human
chooses to mark M3 done on this self-audit alone, that is a human judgment
call, not a strict-protocol one — surface this in CURRENT.md.

### Quiz-me questions (post-APPROVE, per L4 protocol)

1. **Design:** The implementation does `load_key()` once at module import
   (line 93) and never re-validates. Why was that chosen over re-reading
   the env var on each call (which would let you rotate without a restart)
   or over a lazy-init pattern (encrypt-only-on-first-use)?

2. **Edge case:** `conftest.py` line 50 hardcodes a Fernet key for tests.
   If a developer copies that key into `backend/.env` and runs the app
   locally, what happens — does anything break, and what should the SOP
   warn them about?

3. **Change impact:** `decrypt_token` (line 113) raises `InvalidToken` on
   a key mismatch, which the SOP §3.2 says is the "user must reconnect"
   signal. If M4 (LLM input sanitization) ever adds a path that decrypts
   tokens inside an LLM tool call, what does the `InvalidToken` exception
   now mean to the model and to the operator's on-call experience?
